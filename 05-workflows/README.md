# Workflows

Read [Project lifecycle overview](lifecycle-overview.md) first — it is the map, and the rest
of this section is the detail behind each phase.

## The path through a project

| Phase | Document |
| --- | --- |
| 1. Define | [Intake and discovery](intake-and-discovery.md) |
| 2. Design | [Design handoff](design-handoff.md) |
| 3. Build | [Development workflow](development-workflow.md) |
| 4. Ship | [Deployment](deployment.md) · [QA and testing](qa-and-testing.md) |
| 5. Launch | [Launch](launch.md) |
| 6. Hand over | [Client handover](client-handover.md) |
| 7. Maintain | [Aftercare and SLA](aftercare-and-sla.md) |

Sitting outside the sequence: [Site migration](site-migration.md), for when the project is
moving an existing site rather than building a new one.

## Workflows versus templates

These documents describe **how a phase works**. The copyable artefacts that come out of a
phase — briefs, checklists, handover packs — live in [Templates](../08-templates/). So
[Launch](launch.md) explains the cutover, and
[the launch checklist](../08-templates/launch-checklist.md) is what you tick off on the day.
